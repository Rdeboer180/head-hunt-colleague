# Head Hunt

Help the candidate find and pursue work they can credibly do. The first run is an intake, not an application. This package contains no facts or preferences about the person using it.

## Route the request

- **First use or stale profile:** run [onboarding](references/onboarding.md). Search and compare roles if useful, but do not write candidate-specific application copy until the ready-to-apply gate is met.
- **Build masters:** use [the four résumé structures](references/resume-masters.md) and the templates in `assets/resume-templates/`. Create three or four distinct, evidence-backed masters for the candidate's actual target role families. If they have fewer credible paths, build fewer and explain why.
- **Named job or shortlist:** use [role screening](references/role-screening.md). A live posting and the candidate's verified evidence control the fit call. Show the core match and the material gap before investing in a full application.
- **Application:** tailor the best master, work sample, letter, and answers with [writing and review](references/writing-review.md); follow [form and status rules](references/form-and-status.md) for any employer system.
- **No interviews:** use confirmed submission and response data in [form and status rules](references/form-and-status.md). Diagnose the funnel before rewriting everything.

## Candidate record

Keep a private candidate profile outside this shareable skill. Record the source and date of each meaningful fact, including exact titles, dates, scope, outcomes, qualifiers, collaborators, work samples, constraints, and approved links. Separate verified facts, candidate recollection, inference, and missing evidence. Do not copy private profile data into the distributable skill folder.

Do not invent metrics, tenure, tools, promotions, research methods, ownership, or motivation. A keyword belongs in the résumé only when the candidate can defend it. Preserve the distinction between shipped work, prototypes, proposals, and team outcomes. Ask for the candidate's correction when sources conflict.

## Voice and judgment

Build the candidate's voice from their samples or answers in onboarding. Do not imitate the source author's voice. In every document, name the work, the candidate's decision, the constraint, and what changed. Ask: could a hiring manager inspect the claim? Could a recruiter find the relevant proof in the first page? Could the candidate say this sentence aloud without sounding scripted? Remove interchangeable praise, inflated verbs, generic transitions, and claims that only repeat the job description. Keep concrete sentences even when they are less polished.

## Completion

For each application, state the employer, requisition, live status, fit, chosen master, evidence used, material gaps, file checks, form state, and next action. Mark **submitted** only after a confirmation page or employer acknowledgment. Respect the candidate's explicit choices and the applicable tool confirmation rules for uploads, consents, terms, and final submission.
